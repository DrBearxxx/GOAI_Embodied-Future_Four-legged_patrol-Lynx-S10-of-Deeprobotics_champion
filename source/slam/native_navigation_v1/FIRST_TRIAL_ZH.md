# 单次 50 cm 首测：官方运控，一键准备、现场启动

本入口用于**尚未完成正式停车验收的首次现场调试**。不要求 `acceptance.json`，不修改或生成验收通过记录；状态始终注明 `UNVERIFIED`。原 `--execute` 正式导航入口仍保留原验收要求。不要把首测完成理解为长程导航、实际精度或所有故障停车已经通过。

## 最简执行步骤

使用平坦、隔离、无楼梯/边缘的测试区域；路线和终点外留出余量，人员离开运动范围。按用户最新要求，一键首测已允许起点偏移：以当前稳定地图定位生成临时平移的 50 cm 路段，不要求回到原始录制起点，也不修改定位坐标。保持现场监督及机身急停可用；原厂接口开启后不依赖 G12 接管。本脚本不保证主机断电、内核失效、机器人内部网络/接收端失效时仍可自动停车。

### 1. 登录并处理旧运控冲突

Windows：

```powershell
ssh orin-wifi
```

本轮部署时检测到 `xxx` 的 `rl_deploy` 正在运行，**没有由助手停止它**。如果现在仍运行，先让机器人正常趴稳；仅在确认不再依赖该进程支撑站姿时，在 Orin 执行：

```bash
pgrep -a -x rl_deploy
sudo pkill -TERM -x rl_deploy
pgrep -a -x rl_deploy
```

最后一条应没有输出；若本来就未运行，不需要停止任何进程。不要在站立时执行停止旧运控的命令。本入口不会自动杀控制器，也不会改 `xxx/ysc` 的文件或自启配置。

### 2. 一条命令准备首测会话

```bash
cd /home/wym/s10_native_navigation_v1
bash run_first_trial.sh --start
```

创建/进入 tmux 会话 `s10-first-trial`，三个窗口：

- `body`：SSH 连接 `.103` 的 `user` 账户并建立隧道；按提示交互输入密码。显示 `gateway: first_trial`、`physical_acceptance: UNVERIFIED`。此时只有状态心跳，不自动起立或行走。
- `localizer`：启动前后雷达、Insight9 和鲁棒地图定位。已有同一传感器驱动会复用；已有定位/路线实例则启动前拒绝重复创建。
- `route`：上下分栏。**上栏只显示连续状态，下栏固定 `command>` 输入指令，接收结果/拒绝原因/ACK 紧跟该条输入显示**，不再混入上栏滚动日志。用 **Ctrl+B，然后 W** 选择 `route` 窗口，默认焦点在下栏；如果选中了上栏，用 Ctrl+B、下方向键切回下栏。

已有同名会话时仅重新连接，不自动重启或 ARM。默认不带 `--start` 只打印说明，不创建会话、不连接机器人。

### 3. 在 route 窗口逐条操作

下面每条都在 `route` **下栏的 `command>` 后输入并回车**，不是 Bash 命令，也不要整段粘贴。每次输入附带唯一请求编号，下栏只显示与本次请求相符的响应。“网关已下发”不是动作完成；`MODE_NAV/STAND/FLAT/LIE` 还会等待新鲜反馈达到对应状态。如果 2 秒内未确认，下栏返回输入提示符，可以输入 `STATUS` 查看当前状态和上一动作的最终结果；不要重复发送动作。

若输入恰逢票据更新，下栏先显示“等待下一张有效网关票据；尚未发送”，最多等待 350 ms。控制循环继续运行，取得真正有效的新票据且当前条件仍合格后只入队一次；断连、会话/控制来源改变、STOP、QUIT 或超时会取消尚未发送的指令。150 ms 票据时效不延长，已发送指令即使没有 ACK 也不自动重发。已有未完成命令时拒绝叠加新的动作。

1. `SDK_OFF` —— 只接受新鲜、低机身、静止反馈。界面明确显示已下发但没有 `SDKEnable` 回读，不能伪称开关状态已确认。
2. `STAND` —— 请求原厂起立；等反馈确认 `state=17`、高度 0.20–0.65 m、已站稳。首次起立可能触发原厂约 14 s 自动标零，最多观察 40 s，不重复发送 STAND。
3. `MODE_NAV` —— 在站稳后切换，等反馈确认 `mode=1`。此固件在起立后可能恢复 mode=0，因此把切模式放在起立之后；允许连续 2 s 新鲜稳定站姿下显式切换，不再只允许趴下时切换。
4. `FLAT` —— 等 `gait=12290`（`0x3002`）、`mode=1`。
5. `STATUS` 查看 `ready=true`、临时起点/平移量，然后输入 **`ARM`** —— 这一步才开始单次路线行走。每条操作都需显式输入。

若已经站稳而 `mode=0/gait=0x1001`（本次 ARM 报错时的实际状态），直接从 `MODE_NAV → FLAT → STATUS → ARM` 继续，不再输入 SDK_OFF 或 STAND。状态 0 不被改写成 4：首测入口单独要求连续 2 s 的低机身 0.02–0.15 m、静止、姿态和状态一致，才允许从 Idle 起立；常规模式 0 与导航模式 1 均可请求首次起立。实际正向导航要求状态 17、平地步态、站姿高度和控制权全部合格。

`ready=false` 时看上栏 `command.state`、`gateway_reason`；该次指令的拒绝原因/ACK 在下栏，不必回到助手再次授权。常见原因：旧控制器仍在运行、定位不在地图起点、起始朝向不符、避障阻挡、输入过期、两端版本不一致。

### 4. 停止与收尾

- 任意时刻 `STOP` 回车，或 Ctrl+C：请求零速并终止本次路线。网络/接收端故障可能阻碍命令到达，不能把键盘 STOP 当作硬件急停。
- 正常到点显示 `COMPLETE`，保持零速、不自动返回、不自动续走。确认实际静止后输入 `LIE`，确认已趴下，再 `QUIT`。
- 运行中不要 Ctrl+B、D 分离 tmux，也不要关闭 SSH；新入口发现所有操作者终端已分离，会终止路线并请求零速，不自动续跑。终端断连的检测不是硬实时保证。
- 路线结束后，确认机器人已趴下，才在另一个 Orin 终端退出整个首测会话：`tmux kill-session -t s10-first-trial`。
- 传感器驱动是独立进程，需要停止时用 `source /home/wym/s10_slam/env.sh`，然后 `s10slam sensors-stop`、`s10slam camera-stop`。
- 第二次试验需重新准备会话并回到起点；网关和路线均只允许一次 ARM，换 TCP 连接不能重置本次试验许可。

下栏 `HELP` 显示命令；Ctrl+C（包括等待 ACK 时）发送 STOP 并保留输入栏，`QUIT` 退出路线及输入栏。ACK 超时显示“未确认”，不会自动重发，也不会用上一条 ACK 当作成功。不要在上栏盲打，也不要用 Ctrl+S 暂停状态输出。分栏不自动准备模式、起立或 ARM。

如果已经运行的是旧单栏会话，可在另一个 Orin SSH 终端执行下面的命令增加输入栏，不重启路线、不发送机器人指令：

```bash
cd /home/wym/s10_native_navigation_v1
python3 scripts/route_console.py --install
```

## 试验边界

- 一键首测使用原地图路线前 **0.50 m 水平折线**作为形状模板；`--allow-start-offset` 在首次满足稳定定位/感知/模式条件后只绑定一次起点，将这段临时路线平移到当前测量位置，保留原朝向约 0.2344 rad 和原长度。不旋转或篡改定位，不覆盖冻结地图/路线文件。
- 起点绑定要求连续稳定观测窗口，至少 6 个实际地图测量、时间跨度至少 1.5 s；沿用既有 2 s 静止定位判据。临时平移限水平 2 m、高度 0.20 m，不可借此切换楼层。绑定后的起点仍执行 8 cm 就位判据，且不会在 STOP、重定位或漂移后自动随动；需要重新放置临时测试段时须结束本次会话重新准备。
- 正常前进上限 **0.20 m/s**、转向上限 0.20 rad/s，不侧移、不倒走。会缓慢起步并靠近终点减速，不保证达到速度上限。退化、IMU 缺口、避障延迟仍执行更低速度或零速。
- 到点判据 5 cm，需原始地图观测与反馈静止确认。名义路线长度、指令积分、反馈速度积分都不是外部真值；实际行程和停车距离可能不同。
- Orin 和 `.103` 本体各有单次 60 s 上限；本体另限指令积分 0.50 m、转角积分 1.20 rad、反馈速度积分 0.60 m。保留 250 ms 指令租约、过期/重放拒绝、急停反馈、模式/姿态/控制权检查。
- `.103` 的零速伴随进程只持有同一 UDP 连接并发送零速度，不会起立、切模式或发非零速度。网关进程退出或脉冲过期约 0.30 s 时，它先用 pidfd 终止该网关，再尝试连续 2 s 发零速。网关也检查伴随进程新鲜应答。
- 上述是**软件补充措施**，已在随机 loopback UDP 端口做测试，不是实机停车证明。两进程共用同一主机/网络，不能覆盖共同失效，也不能保证原厂接收端收到并执行零速。没有把它称为独立硬件急停。
- 正常到点、STOP、长时感知失效、障碍、控制冲突、超时、网关/定位重启后，首测均不自动续走。短时有效冗余/预测接续保留。

日志在 `/home/wym/s10_native_navigation_v1/live_logs/native-trial50.jsonl`，包含定位、请求速度、本体反馈与 `UNVERIFIED` 首测状态；不覆盖原 10 米路线进度。旧地图、外参和原路线文件不修改。

指令回执单独保存于 `live_logs/command-replies.jsonl`（有界滚动），包含请求编号、路线 PID、ACK/拒绝原因；下栏通过编号关联，不创建第二个网关连接。

## 原厂 DDS 端点识别（2026-09-20 修复）

原厂 `motion_master` 的 `/JOINTS_CMD` 与 `robot_server` 的 `/GAIT` 是正常内部通路，不能仅按发布者数量判为外部控制器。当前实现按 Fast DDS 参与者前缀、类型、原生命名空间及相关状态端点关联；运动参与者还要求实际收到新鲜 `/MOTION_INFO`。Jazzy Python 不提供 publisher_gid 时仅使用唯一发布者图关联。

原厂 handler/planner 公告但静默的 `/NAV_CMD` 可保留，分别通过 `/OOA_STATUS`、`/PLANNER_STATUS` 角色端点关联，并要求拓扑稳定与至少 1 s 没有导航速度流。事件型状态没有更新不被伪造为已确认 idle。任何实际 `/NAV_CMD`（包括零值）都仍触发竞争检测；未知发布者、已发现非 idle handler、拓扑改变、缺少必要遥测或旧控制进程仍会阻止动作/终止首测。禁止在此测试中同时运行原厂自主导航任务。

这是一项运行期冲突监测，不是 DDS 身份认证或接收端原子控制锁；不能保证外部控制器开始发指令与检测之间没有延迟。没有按通用 bare-DDS 名字全局放行，没有关闭未知原厂进程，也没有修改 50 cm/0.2 m/s/单次许可约束。
