# 实机数据异常鲁棒性 V2（2026-09-14）

本版目标是容忍有界的短时数据缺陷，不要求每个传感器永远满帧；不以放宽配准几何标准、伪造时间戳或忽略真实障碍换取连续行走。只用于当前室内前 10 米的低速试验，不能替代楼梯/悬崖/负障碍检测。

## 已实现的状态和边界

| 数据状态 | 导航行为 |
| --- | --- |
| 双雷达几何观测新鲜、IMU 连续、避障新鲜 | TRACKING；速度指令上限 0.10 m/s、0.20 rad/s |
| 单雷达匹配短时缺失，或上次几何观测年龄 0.25–0.35 秒 | DEGRADED；最多 0.04 m/s、0.10 rad/s |
| 几何观测年龄 0.35–0.55 秒，仍有连续惯性路径，预测位移和误差预算未超限 | PREDICT_ONLY；最多 0.02 m/s、0.06 rad/s，不确认到达 waypoint |
| 全部 IMU 暂时迟到 40–80 ms | 仅保留最后积分时刻的估计；最多 0.02 m/s，不转弯，不补造缺失 IMU |
| 最近一次双雷达无障碍证据年龄 0.25–0.40 秒 | 扩大正障碍安全区后，只允许最多 0.02 m/s、不转弯；缺少任一侧历史覆盖不适用 |
| 数据超过上述边界、共同 IMU 缺口使积分不连续、预算超限、发现障碍 | 锁止停车；数据恢复不自动续走 |

上述是**工程试验上限，不是已标定的统计置信区间或物理安全保证**。实际估计速度越高，0.15 米预测位移上限越早触发；导航另外拒绝估计机身速度超过 0.5 m/s。速度表是发送目标上限，GOAI 本身有平滑环节，不能解释为机身瞬间达到该速度或立即静止。

短时降级未停车时，可自动恢复，但恢复全速前保持 0.5 秒限速。新启动/重新授权要求连续 2 秒 TRACKING 和新鲜双侧避障；停车后仍须 A 回手动，再 ROUTE-READY → NAV-READY → C。路线点顺序不变，预测不越点。

## 数据链路

- 雷达正障碍处理独立进程，与耗时 GICP 配准解耦；每侧队列仅保留最新帧，过期积压不能刷新避障证据。动态人只可从建图点云中滤除，不能从实时避障中忽略。
- 优先使用一条完整 IMU 链；前后 IMU 都不完整时，只在有实测覆盖、重叠且角速度一致的区间拼接。共同缺口不强行插值。相机完全掉线时允许仅雷达/雷达 IMU 定位。
- 每个传感器独立时钟 epoch 和隔离；乱序/重复/跳变不作为新观测。单路重启不直接清空可用的其他路。跨共同缺口或重定位仍可能需要重新授权。
- 保留 measurement_mono 和 estimate_mono，定时器仅更新估计输出时间，不能延长测量寿命。大幅重关联修正触发重新授权。
- 估计输出 50 Hz，与 25 Hz 导航解耦；避免低频发布本身反复触发 IMU 到达时效降级。
- 只隔离可识别的坏输入包；工作进程崩溃、错误坐标系、格式无效、重复发布者仍显式失效。
- 未修改 GOAI 模型、关节反馈期限、G12 许可/接管、独立速度输入超时、冻结地图/外参/66 点原路线。

## 验证与使用

使用原 `run_goai_localizer.sh` / `run_goai_route.sh` 入口。默认只读，不发运动指令。`scripts/verify_goai_overlay.py` 校验 V2 文件和冻结依赖；回滚备份独立保存，不覆盖 V1 历史。

单元测试：`python3 -m unittest discover -s tests -v`（需现有 SciPy 环境）。

实录因果回放：`python3 scripts/replay_robustness.py --faults --output results/新的输出目录`。

隔离真实 GOAI 测试：`bash run_goai_isolated_test.sh`，强制 loopback 187/188 域，关节/传感器输入全部为合成，不触达实机控制域。

审核报告保留旧严格时效比例；新增 `v2_estimate_available_fraction` 只表示估计可用，不代表障碍清空、运动放行或绝对定位精度。实录回放不等于实机调度验收，采集速度也不能直接当作 0.10 m/s 导航的控制测试。本轮未授权机器人真实行走。
